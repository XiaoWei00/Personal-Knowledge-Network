# 绑定

一句话：绑定是把一段认证限定在上下文里，使它不能脱离这个上下文被复用。

## 为什么存在

校验值或签名原本只回答「谁对哪些字节做过什么」：

```
tag = F(密钥, 内容)
```

它没有说这些字节属于哪次会话、哪个地址、哪个方向、哪笔交易。攻击者可以把一个有效的 tag 挪到另一个上下文里——只要接收方还在用同一把密钥、还在验同样的内容，它就能通过。

绑定把上下文写进认证：

```
tag = F(密钥, 上下文 || 内容)
```

或者用上下文派生专用密钥：

```
上下文密钥 = KDF(主密钥, 上下文)
tag = F(上下文密钥, 内容)
```

这下 tag 的含义变成：「持有密钥的人认证了这段内容，而且它属于这个上下文。」改了上下文，tag 就失效。

## 三个问题

| 问题 | 机制 | 缺失后果 |
|---|---|---|
| 谁发的？ | 认证 | 伪造 |
| 是不是新的？ | 新鲜度 | 重放 |
| 是不是给这里的？ | 绑定 | 挪用、反射、跨会话、跨地址 |

一条消息可以很新，但地址错了；也可以地址对，但很旧；也可以又新又对，但是伪造的。三者都成立，接收方才敢用。绑定和新鲜度是两件事，不能互相替代。

## 绑定维度

- 身份：这条认证属于哪个主体。TLS 的 CertificateVerify 把服务器身份绑进握手；JWT 的 `iss`/`sub` 绑定签发者和主体。
- 会话：这条认证属于哪次会话。TLS 的 transcript 包含双方新鲜随机数；旧会话的签名搬不过来。
- 方向：这条消息是哪个方向发的。TLS 每个方向一把密钥；RPMB 的请求/响应类型进 MAC。否则可以把消息反射回去。
- 通道：这条认证属于哪条通道。应用层可以把认证绑到 TLS 通道（channel binding），防止中间人把认证转接到另一条通道。
- 地址：这条数据属于哪个位置。RPMB 的地址和块数进 MAC；否则可以把 A 槽的数据剪到 B 槽。
- 类型/用途：这条消息是读还是写、是请求还是响应。RPMB 的类型进 MAC；否则可以反射或误用。
- 事务：这条授权对应哪笔交易。签名必须覆盖金额、收款人、订单号；否则一个「同意」可以挪到另一笔交易。
- 协议：这条认证属于哪个协议。用上下文串或不同的密钥做域分离，防止跨协议复用签名。

## 例子

- TLS 的 CertificateVerify 签的是「上下文串 + 握手 transcript 哈希」。如果不绑 transcript，服务器长期私钥不变，旧会话的签名搬到新会话仍然有效；绑定后只对那次握手有效。
- TLS 的记录头进 AAD，密文不能脱离它的分帧被解释；每方向密钥让旧记录搬到反方向也解不开。
- RPMB 的 MAC 覆盖地址、块数、请求类型、写计数器、nonce。少绑一个，就多一种剪贴、反射或重放。
- JWT 的 `aud` 绑定受众：给服务 A 的令牌不能拿去服务 B 用。
